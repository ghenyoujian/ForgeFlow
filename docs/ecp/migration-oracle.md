# P0-02 migration expectation research

`verification/ecp/migration_oracle.py` compares **caller-supplied in-memory declarations** with an expected migration inventory. It does not read migration files, connect to PostgreSQL, start SQLx, execute SQL, inspect a compiled binary, authenticate a principal or issue a product Gate. Its reports always carry `qualification=NOT_RUN` and `product_gate_effect=NONE`; `MATCH_DECLARED` means only that the supplied objects agree under this research policy.

`inventory(entries)` accepts a list of exact dictionaries containing a filename and its raw SQL bytes, and emits the expected forward and down versions, SQLx-style descriptions, byte counts, SHA-384 checksums and separate SHA-256 content labels. `compare(entries, rows, source_complete_claim=..., row_complete_claim=...)` additionally accepts declared database rows with version, description, success and lowercase SHA-384 hex. Both completeness flags are unverified caller claims. Missing or extra versions are only treated as declared mismatches when the corresponding opposite set is claimed complete; otherwise they remain in the `unconfirmed` lists. Common-version conflicts and every supplied `success=false` row remain mismatches even when either set is incomplete. Input and row-set digests label contents; they do not authenticate a source, row, principal, database or completeness claim.

The expected filename and checksum rules were studied against the locally observed SQLx 0.8.6 source selected in `Cargo.lock`, not independently verified against a running binary. The observer permits an up/down pair of the same version, and conservatively rejects ambiguous multiple forward or multiple down files and orphan downs. It flags description disagreements even though SQLx `run_direct` does not itself compare stored description; these are stricter research policies, not claims about SQLx runtime rejection. Limits on count, bytes and description Unicode likewise express local safety policy. `OracleInputError.code` identifies a rejected input; a rejection is not a product result.

The caller remains responsible for a complete, stable, independently authenticated file inventory and database read, including filesystem type, source/build identity, SQLx embedded migrations, database/server and connection identity, principal/lease, transaction and historical-fixture evidence. This module does not establish those properties; without them the real P0-02 and G0 remain `NOT_RUN` or `BLOCKED`.

Run the synthetic tests from the control root with `python3 -I -S -B verification/ecp/test_migration_oracle.py -v`. The test imports the sibling `migration_oracle.py` by `__file__` and uses only in-memory inputs. A passing test run establishes the tested mapping only; it does not execute a migration or demonstrate database validity.
