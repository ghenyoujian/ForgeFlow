# P0-01 dirty-source collector — research only

`verification/ecp/dirty_source/collector.py` is a bounded research collector, not a production entry point or a P0-01/G0 qualification. It accepts an already-open caller-owned source-directory FD, an injected Git runner and the sibling dirty-source model. It has no CLI, does not launch Git itself, and never resets, cleans or intentionally writes the supplied source. Reading the source, its ancestors and Git metadata can nevertheless update access times; before/after samples do not authenticate continuous immutability.

The collector requests HEAD, tree, stage-0 index, index flags and individual blob bytes from the supplied runner; it recomputes each Git object ID. It scans the worktree twice using bounded, streaming, no-follow directory traversal and represents HEAD, index, tracked worktree and untracked files separately. Files ignored by Git are included in the scanned untracked set, not silently excluded. It rejects unsupported types, empty directories, nested or linked Git, hardlinks, cross-device entries, malformed rows, hidden/multistage index entries, bounds excess and observed endpoint changes. Same-device bind mounts cannot be detected by this test. Successful observations are non-atomic and explicitly retain `qualification=NOT_RUN`, `product_gate_effect=NONE`, unverified caller/feature authority and unknown snapshot atomicity.

The caller must independently establish the runner is bound to the same source root, uses a trustworthy bounded execution boundary and excludes unsupported features including intent-to-add, sparse checkout/index, external filters/LFS, alternate objects, submodules, path aliases and hostile concurrent changes. The required boolean `unsupported_features_excluded=True` is only the caller's unverified assertion; absent independent evidence, treat the result as NOT_RUN/INCONCLUSIVE. `executable_mode_observed=True` also requires an independently trusted filesystem and Git configuration. Otherwise pass `False`, which records regular-file executable mode as unknown rather than inferring it from the index. Neither assertion establishes principal, lease, source identity or completeness.

**`sandbox_git_runner.py` is for explicitly reviewed disposable synthetic fixtures only. Do not use it on a user or production worktree.** It starts the fixed Git plumbing commands, writes exclusive capture files to the supplied fixture log directory and preserves bounded stream samples and command status on failure. It has no wall-clock timeout, no signal/cleanup policy and no proof that descendants have stopped. A stuck or unconfirmed child is UNKNOWN. The caller must provide isolation, process supervision and resource controls; same-device bind mounts, runtime identity and later writers remain unverified. The adapter is not wired into the product verifier and provides no automatic production command.

A single independently reviewed synthetic real-Git run exercised the collector on 5 HEAD, 6 index, 5 tracked-worktree and 2 untracked entries, including an ignored file, and compared saved pre/post Git observations and non-atime inventory endpoints. See the [synthetic observation receipt](/home/chenyoujian/.cache/forgeflow-g0-continuation-20261116/r39-p001-collector-git-integration-run-v2/receipt.json). This one fixture cannot establish general Git correctness, source immutability, safe use on the actual worktree, reconstruction, process-tree termination or a Gate.

The synthetic tests can be run with `python3 -I -S -B verification/ecp/dirty_source/test_collector.py`. By default each test creates and retains a new private `forgeflow-collector-test-*` directory under the system temporary directory. Set `ECP_COLLECTOR_FIXTURE_ROOT` to an existing private empty directory to confine fixtures there; the test creates one uniquely named child per method and leaves it in place. These tests mock Git subprocesses and do not connect to a database. Their success does not grant product qualification.
