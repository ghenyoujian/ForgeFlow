# Managed native children

`managed-sandbox.mjs` supplies a separate native Node process provider for an installed DSH checkout without its optional Landlock binary. Preparation compiles the unchanged official C into a private immutable binary and freezes its source, compiler and output hashes. Its original enforcement verdict remains `partial` on Landlock ABI3. The project `native-ioctl-deny.c` adds an inherited seccomp filter that refuses ioctl except the ABI5-exempt FIONBIO used by Node pipe setup, validates the syscall architecture and rejects x32/compat bypass. ABI3 already governs all filesystem bits in the official ABI5 mask except device ioctl. The exemption is part of the [Linux kernel Landlock ABI5 contract](https://docs.kernel.org/userspace-api/landlock.html#filesystem-flags). The combination covers that native filesystem/device surface; it does not claim full network, billing or descendant containment. The outer Worker's bwrap, disabled nested user namespaces, exact mounts and Landlock remain mandatory.

Run `qualification/canonical-collaboration/prepare.py` for a reusable managed overlay. Add `--qualification` only for the explicit finite collaboration probe; ordinary preparation omits that tool. Both use the same pinned provider and launchers. A successful host probe alone does not qualify a Workflow. The zero-model native PTC probe must also demonstrate permitted temporary file actions, denied write/rename/truncate/symlink outside the outer exact write set, and inherited ioctl denial. Missing launchers, drift, ABI<3, filter failure or incomplete positive probes fail closed.

`managed-bridge.mjs` is an additive Cordis plugin on supported DSH extension points. It changes no native DSH packages or personal configuration. The awaited `agent/created` hook reserves each root or in-process child before queued work starts. `agent/request` installs the controller's provider/model/output cap through the logged native request configuration, including each cold resume. `llm/stream` denies unallocated or unattributed calls and records every intercepted request and settlement, including auxiliary title calls. Workflow and subagent lifecycle events are observations, never grants.

The installed DSH runtime supplies `agent/created` as an awaited serial hook after scoped child setup and before queued input can run. Native Agent Teams writes and flushes its `team/member` provisioning record before creating that child. The additive `team-binding.mjs` service uses that actual record to select the corresponding declared project position preset through `agentPresets.select()`. The bridge also awaits `forgeflowTeamBinding.bindAgent(agent)` inside its own creation hook, so sibling plugin registration order cannot allow an admitted child to run under an unbound preset. A missing optional binding service retains the generic managed profile; a declared binding failure rejects creation. Preset selection does not grant resource, model, filesystem or integration rights.

Fresh teammates can select their declared preset before the first turn. Native `select()` rejects a different selection after a completed or inherited turn; the overlay preserves that restriction. A cold resume reconstructs its exact durable selection, and an ordinary Workflow/one-shot child inherits its parent's native composition. The native Workflow `agent()` options do not contain a preset selector. A task-specific role prompt is supported there; treating an invented `preset` option as a real selection is unsupported.

The selected model route, per-call output cap, total requests, model concurrency, live Agent slots, total lifecycles and depth are finite. The Worker relay sends every request to the authenticated canonical API; PostgreSQL issues and persists every grant under the claimed parent attempt, lease, generation and resource policy. The relay never grants locally. A revoked identity cannot receive further admissions or model requests. Process loss does not release allocations or unknown model reservations.

Every RPC request line carries `schema_version: forgeflow.dsh-bridge.v2`, UUID `rpc_id`, `operation`, `project_id`, `task_id`, `attempt_id` and `generation`. The bridge generates `rpc_id` once per logical request and reuses the exact serialized request for its single bounded transport retry. PostgreSQL persists mutation and observation request/reply identity; a changed payload using that durable UUID is rejected. `poll` is an authenticated read: every retry observes current revocation and does not create a durable mutation receipt. All replies carry `ok` and `generation`; rejection adds `code`. The bridge rejects a successful reply with a different generation. The private Unix socket permits one bounded request/reply exchange per connection, at most 64KiB. Missing controller access fails closed; it never falls back to unmanaged DSH.

Native observations use one ordered RPC tail per managed process. Admission, model permits, settlements and actual disposal releases remain independent awaited RPCs. This keeps a Team event burst from occupying all controller connections while its children are being admitted; no observation is dropped and no successful receipt is manufactured. An observation failure retains its original rejected operation and closes admission. Teardown drains all tracked original operations. Events published during a real creation hook are buffered until its canonical grant commits; rejected creations cannot manufacture an attributed lifecycle. The RPC decoder preserves UTF-8 across socket chunk boundaries.

The observation whitelist includes the installed runtime's durable `team/member`, `team/task`, `team/message/queued`, `team/message/delivered`, `agent-preset/selected`, `tool-workflow/*` records and its actual `agent/status`, `subagent/*`, `workflow/*` notifications. Team member observations retain native Team/child identity, name, provider, context and phase. Native task observations retain ID, revision, status, optional owner ID and dependency/write-scope counts. Mailbox events retain message/sender/target IDs only. Workflow traces retain run/member/child identity, labels, phases and outcomes; member sequence is separate from the enclosing durable session event sequence. Preset and position facts are visible in the canonical lifecycle's original `admission.agent_options` even if native preset selection preceded the bridge listener. Prompts, descriptions, errors, tool arguments and message bodies are excluded. All values are capped at 16 KiB, nested schemas reject unknown fields, and a named native session must belong to an admitted lifecycle of the same attempt. These records carry `grants_authority: false`.

Periodic revocation checks default to one second per managed process. The trusted Worker validates frozen parent identity and forwards each poll as a fresh canonical read; it does not create a per-poll request journal. The store checks the current immutable Worker/task/generation binding, attempt state, lease expiry/fence and native revocation without taking mutation locks or inserting `native_bridge_rpc`/event rows. Historical durable UUID conflicts remain rejected. Original admission, model, observation and release operations retain their immutable journal and durable replay behavior. A successful poll establishes the observed revocation state only; it proves no model, financial or business completion.

Revocation belongs to the authenticated canonical controller. Native callers cannot revoke, release root resources or attest process stop. `generation` alone is not an OS sandbox or billing account. Canonical admission atomically binds each native child to the parent execution, reserves the seven resource dimensions across global/project/team-ancestor/Worker scopes, issues the allocation, and rejects stale release/model settlements. The Worker binds the socket and journal to its exact owned native process. Unknown reservations remain held or quarantined pending trusted reconciliation.

Cancellation closes new admissions, calls native `Agent.cancel()` on every tracked Agent, waits for whole-Agent idle and every intercepted model stream settlement, then reports a quiescence acknowledgement. Idle is not a per-message result or business completion. The controller independently rejects acknowledgements with omitted active allocations, reported non-idle Agent statuses or unsettled/quarantined model requests. It does not directly inspect native Agent state. A stuck auxiliary call requires Worker process cancellation; this plugin does not replace process supervision.

Native child disposals request release with `reason: native_disposed`; the store waits for their model reservations and descendants to close before returning charged resources. DSH unloads the external plugin before the root registry's final disposal; the root borrows the parent attempt reservation and remains live until the trusted Worker observes positive process-stop evidence. Managed mode requires the frozen namespace/Landlock sandbox. A parent PID stop alone does not establish whole-pool containment. Closing orphan children through the physical-stop path additionally requires the actual trusted stop receipt to match the immutable whole-pool binding and demonstrate its empty owned cgroup. That physical fact does not settle unknown model usage.

Native child concurrency and canonical card concurrency are separate. A Team/Workflow child stays inside its parent's claimed attempt, worktree, immutable execution envelope and exact write set. Native Team task completion is a durable coordination observation; it cannot complete a ForgeFlow task, unlock a formal dependency or advance main. Cards owned by different code Owners require their own canonical attempts and leases. Twenty or more card-level Workers can run alongside bounded native delegation, subject to the actual aggregate CPU, memory, disk, GPU and model policy. Native Team `writeScopes` alone does not install a separate operating-system boundary for each child. Increasing a YAML member limit is configuration, not evidence of twenty simultaneous native lifecycles or model requests.

Raw provider usage is preserved. `usage_complete` is false for missing, abandoned, aborted or error outcomes, even when native adapters emit zero counters. Unknown cost is never normalized to zero; a canonical budget retains or reconciles its reservation. Input buckets are disjoint: uncached input plus cache read plus cache write; reasoning is an output subset. Durable assistant events corroborate transcript settlement without recounting inherited fork history. No monetary price or complete billing total is asserted.

Only local in-process providers share these hooks. The preset's workflow/subagent/team routes use spawn/fork. Remote Codex, Claude, ACP or DSH-SDK subagent providers need their own controller bridge; their absence of a local Agent cannot earn child qualification. Arbitrary shell/filesystem/network egress also requires separate process-level enforcement. Qualification must state the pinned runtime, profile, policy, actual simultaneous lifecycle/model counts, result denominator and independent evidence. A historical finite pass does not establish an expanded twenty-channel workload or all production obligations. The archived v1 receipts prove their historical local workload only; they do not qualify this v2 runtime. Actual canonical receipts belong in `qualification/canonical-collaboration`; customer-project delivery evidence remains in its own external project report.

No plugin unload, missing PID, native `idle` status, a model response or a self-reported completed Team task settles an unknown request. Previously quarantined requests keep their original allocations and usage-unknown state until trusted reconciliation. This overlay does not repair those records by setting fabricated counters or forcing resource release. The user-selected GLM5.3 Max route must be frozen by the canonical parent profile, and every native permit must select that exact route; the bridge contains no alternative provider fallback. A new profile's explicit provider policy is passed as the paired `provider_policy_id: glm-5.3-max.v1` and `provider_policy_path: /tmp/forgeflow/provider-policy.json`; the bridge rejects a partial or different pair and preserves that selection in the immutable model transport configuration. The Worker must separately pin and mount the policy file.

The model response idle timeout remains finite and frozen per profile, with a maximum of `1800000` milliseconds (30 minutes). This ceiling permits explicitly configured quiet GLM5.3 Max response tails that exceeded the former 5-minute validation limit; it does not change the chosen timeout of an existing profile. The installed native provider's stream-idle setting and the trusted Worker relay must agree with that profile. The parent attempt deadline, provider request ceiling, model grant, Max reasoning policy and 131072-token ceiling remain separate bounds. An idle timeout, abort or total deadline still preserves incomplete usage as unknown rather than declaring a model request settled.

For a fresh author profile with read-only worktree parents and writable file mounts, `exact-leaf-filesystem.mjs` replaces the stock `fs-sandbox` provider. The stock writer requires a same-parent staging directory and rename, which file-level Bwrap mounts intentionally deny. The replacement inherits the installed native provider's reads, resolution and stat/version contract. Write/edit operations require both the current native initiator's live canonical grant and the Worker's frozen `exact_write_binding`: schema `forgeflow.exact-leaf-write.v1`, actual isolated `workspace_root`, and the original envelope's exact relative `write_set`. The bridge exposes that binding as the immutable `forgeflowExactWriteBinding` service. Missing bindings and read-only calls deny every mutation; the Inspector retains the stock read-only provider.

The author provider opens only an already mounted regular leaf with `O_RDWR | O_NOFOLLOW`, rejects symlink aliases and hard-linked targets, preserves observed-version guards, serializes mutations per target and respects a narrower per-call workspace policy. It writes and fsyncs the same descriptor without creating, renaming, linking, chmodding or making a parent writable. Text edits preserve native literal-match and CRLF behavior. A finite byte bound limits the retained preimage; a handled I/O failure restores that preimage on the same descriptor. These are in-place writes, not crash-atomic publication: a process kill can leave a partial candidate, which still requires the ordinary exact-diff check, positive process stop and independent verification before integration. Existing profiles and active attempts are never patched to enable this provider.
