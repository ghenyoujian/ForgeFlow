# Flow compiler

`forgeflow-planner` is deterministic and has no database or executor authority. Canonical project/task/Flow types come from `forgeflow-domain`; semantic `TaskSpec` and immutable source snapshots are carried in a `CompileContext`. `Store` owns authoritative save, approval, admission and resource transactions.

The public sequence is:

1. `normalize_requirements(source_document, text, Markdown|Json)` preserves raw SHA256, semantic SHA256 and source anchors. JSON rejects duplicate keys recursively, unknown typed fields and integer/boolean confusion.
2. `rules_based_draft` creates an explicitly labeled editable scaffold. Its acceptance case count starts at zero so the scaffold cannot accidentally pass compilation. It is not DSH-assisted decomposition.
3. For DSH planning, `model_draft_prompt` creates the bounded task prompt; a normal read-only PLANNING Attempt must pass the same resource/lease/worker authority as any other attempt. Preserve the raw output artifact. `validate_model_draft(output, request)` strictly parses the result and checks original source/request identity, unchanged acceptance and approved write authority. Model output must never be treated as owner, input or contract authority. The API replaces those fields from trusted store snapshots. `model_repair_prompt` supports a bounded formatting repair, not scope/acceptance reduction.
4. `canonical_task_input_digest(task,spec)` seals task scope, ownership, references and semantic inputs. `compile(flow,context)` returns typed findings, actual cycle paths, precise blocked cards, coverage and deterministic topological order. It checks dangling/duplicate references, source drift, mandatory input deletion, future producer closure, Owner includes/excludes, resolved symlink targets, unordered intersecting writes, four-party frozen contract inputs and nonzero verification plans.
5. `freeze(flow,context,actor,expected_revision)` returns an immutable committed candidate only when compilation passes and the editable row revision matches. Persistence/CAS and trusted snapshot revalidation must occur in `Store`; this function grants no lease.

`task_input_digest(spec)` is a spec-only helper, **not** the canonical task context identity. `canonical_task_input_digest` uses the versioned `forgeflow.task.input.v2` algorithm, excludes Flow rebinding and derived rendered prompt/context hashes, and retains the immutable task revision. `semantic_digest(flow,context)` uses `forgeflow.flow.approval.v2`, binds the Flow version and normalized static execution template, and excludes observation timestamps, approval actor, row revisions and runtime-issued envelope identities. CheckReport publishes both algorithm labels; its input_digest is the Flow approval identity. The envelope template includes pinned prompt/context bytes and profile/plan IDs, effects and enforcement; the compiler requires the declared profile, plan and write scope to match. Rendered prompts can embed the Task input digest but must never embed the final Flow approval digest, which would create a hash cycle. Removed/deferred plan membership remains semantic. Heartbeats cannot invalidate this digest.

Dependency edges carry `integrated`, `artifact`, `contract_frozen` or `gate_pass`. Runtime readiness is checked by the Store against matching immutable receipt identities. Schedule dates do not create execution dependencies. Cross-project task edges are rejected unless represented as an explicit versioned delivery contract; the first compiler deliberately does not invent implicit cross-project readiness.

Run checks from the repository root with the shared build permit:

```sh
CARGO_TARGET_DIR=/home/chenyoujian/.cache/forgeflow-control-target CARGO_BUILD_JOBS=2 cargo test -p forgeflow-planner
```

Tests cover a 10,000-card DAG using an independent elimination oracle and negative cases for cycle impact, dangling references, territory, coverage, self-rehashed missing mandatory input, input drift, future producers, symlink aliases, contracts and strict JSON identity. These tests prove local compiler behavior, not DSH model-assisted planning, actual source filesystem isolation, full API persistence or product Gate passage. Model-assisted qualification requires real DSH PLANNING output and request/source-bound review evidence. `planning_bootstrap_with_source_input` creates one finite read-only proposal with a separately pinned controlled source artifact path; runtime approval, actual DSH output and independently executed validation remain required. `diff_flows` reports whole-graph affected task closure and active Attempt IDs without changing their identities. `task_binding_equivalent` allows only unchanged active definitions to bind a new Flow; Store must also compare ancestor dependency TaskCards in old and new revisions. Existing historical digests are never rewritten or silently relabeled as the new algorithm. A format upgrade needs an explicit newly checked revision, with old source/attempt snapshots preserved.
