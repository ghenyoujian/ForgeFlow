# Managed Git and evidence

`init_managed_repository(Some(source), bare_destination)` creates a separate bare authority without altering the source checkout. A `None` source creates an empty bare repository; a project must create its first commit before attempts can use it. `prepare_worktree(repo, base_sha, attempt_id, destination)` creates an independent `attempt/{id}` branch and linked worktree. Persist the returned `WorktreeRecord` together with the project's repository ID, target ref and lifecycle state. Existing destinations or branch IDs are rejected. No helper deletes failed, dirty or conflict worktrees.

For an executor with a private mount namespace, `prepare_isolated_repository` creates a full local clone using `--no-local --no-hardlinks`, removes its bootstrap remote and provenance logs, and checks out the attempt branch. Its Git objects, refs, index and config are independent; `.git` is a directory rather than a linked worktree pointer. The record reports clone milliseconds, object file count and object bytes. This full-copy profile consumes storage per attempt and scans metadata when auditing; small fixture measurements do not establish industrial repository throughput. The Worker must mount only the private repository and required tools, with canonical metadata absent. `PRIVATE_GIT_METADATA` describes this factory result; an OS isolation claim additionally requires an actually launched, verified Worker guard.

After the executor is stopped, `verify_private_repository` rejects metadata symlinks, shared hardlinks, alternates, commondir pointers and executable or external-pointer configuration. Mechanical commands force the private Git/worktree locations and disable ambient configuration, fsmonitor, textconv and external diff helpers. The safe config profile admits basic core format/file settings and identity settings; repository-defined filters and includes need a separately supported policy and are rejected. Strong callers use `audit_private_worktree` and `freeze_private_candidate`, which require private metadata even if an executor replaces `.git` with a linked pointer. The controller's durable worktree record selects the profile; a mutable file inside the workspace cannot downgrade it.

The server calls `import_candidate(canonical, private_worktree, candidate, attempt_id, scope)` after independent verification and a fresh scope audit. It checks frozen SHA/source/manifest identities and all residual dirt, then transfers only that candidate identity into `refs/forgeflow/candidates/{attempt_id}` using Git upload-pack/fetch. The transfer is idempotent and cannot advance main. Canonical source objects then support authoritative Store checks and the normal integration lane. [Git upload-pack documentation](https://git-scm.com/docs/git-upload-pack) describes its safe untrusted-repository transport and refusal of lazy fetches; mechanical commands preserve that restriction.

`audit_worktree(worktree, base_sha, scope)` examines base-to-HEAD, index, disk, and all untracked paths, including ignored paths. `owner_paths` and `write_set` are intersected: an exact file is written as `src/file.rs`; an explicitly permitted subtree ends in `/`. Patterns are not interpreted. Both sides of a rename and original delete paths are checked. Escaped symlink targets, submodule updates and special files are rejected. Rejected full binary diff, statuses and untracked bytes are saved in the private Git metadata as `forgeflow-rejected-diff.json`.

The caller must stop the executor and confirm its process group is quiescent before `freeze_candidate`. That function audits every observed change before staging explicit paths. It audits the resulting candidate again. It never attempts to rescue an illegal attempt by staging only legal files.

`IntegrationService::integrate` acquires one static process-wide lane shared by every service instance and repository, followed by a nonblocking repository-wide OS file lock. The initial deployment profile has one authority server. The OS lock serializes the same repository across processes; global capacity across multiple server processes would require a durable database permit and is not claimed. Bypassing Git commands by another trusted local process is detected by the reference CAS, not prevented by this library. The service refuses unresolved durable intents, reads current main, merges the candidate into an independent integration worktree, preserves real conflict files, and calls the trusted independent verifier against the new integrated commit. The supplied binding must identify the original base/candidate/attempt/generation and frozen task inputs.

The integration candidate also uses private Git metadata, so verifier Git queries work without a canonical mount. The verifier callback writes logs/reports beneath `integration_verification_root(workspace)`, a sibling scratch directory, while source and its `.git` remain read-only. `log_path` is relative to that scratch root and `log_hash` is its SHA256. Logs must be nonempty, confined, and byte-identical. After the group settles, the controller rechecks frozen bytes, imports the integrated commit into canonical objects, snapshots the raw log/receipt under `canonical/forgeflow-evidence/{intent_id}` and syncs that controller-only directory. It then persists PREPARED and COMMIT_DECIDED through `IntegrationStore`. Only after the durable decision does it CAS the bare target ref and record REF_UPDATED then FINALIZED through the Store. The PostgreSQL implementation owns authority checks and cancellation semantics.

`recover` loads the existing intent, validates its stored receipt, raw artifact and source tree, and either completes the already decided CAS or confirms the observed new SHA. An uncertain decision or finalization acknowledgement returns `GitError::CommitInProgress` containing the original intent ID and integration SHA; callers report an unresolved result and recover that same intent. A DB timeout after ref advancement remains recoverable without reapplying the candidate. Unexpected refs, including unexplained descendants, fail closed with `MERGE_DIVERGED` and are recorded as recovery-required; auditing subsequent writer provenance is required before any operator confirmation. Recovery never resets main. PREPARED intents are aborted through the Store command API; the library does not invent a commit decision.

Linked worktrees remain available for trusted server integration and share Git metadata. Executor isolation uses the private-repository factory plus Worker OS guards. The APIs reject non-bare integration repositories and never modify a checked-out user branch. Per-file runtime restrictions, actual Worker namespace launch evidence and durable worktree lifecycle registration are separate Worker/Store responsibilities.
